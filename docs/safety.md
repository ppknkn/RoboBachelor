# 原 STOP 行为与软件边界

按作者最终要求，本版恢复原控制策略：初始化和约2秒IMU收敛后请求使能4个DM关节与2个JC轮电机；没有ARM/DISARM串口命令，没有新增遥控帧超时/失联保护，也没有编译期永久禁能宏。

`robot_logic_update` 仍以原解析值 **g_rc.sw1==0** 进入ROBOT_ESTOP，其他值走原STANDUP→BALANCE→DRIVE流程。退出STOP不要求新增解锁动作。没有猜测真实RF209S通道并替换解析器，也未改原UART数据位/反相配置。用户记得原拨杆可STOP，但本轮没有实测其字节映射。详见[接收机记录](receiver-rf209s.md)。

保留的STOP缺陷修复是：清零速度/转向目标与位置保持积分；STOP时主循环不再发送新的MIT关节位置/速度目标，并持续请求零轮力矩。关节可能仍保持旧的内部目标，CAN入队不代表电机响应；**STOP不等于卸力或物理断电**。停止命令没有被包装成认证级急停。

原超过1rad倾角的motor-disable锁存路径保留；新增IMU后端无效/非有限姿态也进入同一路径，初始化失败则在使能前退出。这些传感器错误处理不改变正常PID参数，也不是新增遥控保护。原JC动作寄存器值按开发者协议更正为1；实际卸力/ACK未验证。

RF209S当前设HOLD，可能持续发送最后通道值，因此失去无线信号后机器人可能继续原指令。本版不声称检测RF失联。没有独立watchdog、完整电机反馈超时或硬件断电链验证。首次检查和采集应断开电机动力，准备独立物理断电，不能依赖软件STOP承担人身安全功能。没有进行本轮硬件测试。
